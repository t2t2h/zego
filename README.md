# Aflatoon Suite — DomainSniffer + ServerTester في مشروع واحد (Theos)

© أفلاطون (Aflatoon / Plato) — جميع الحقوق محفوظة.

دylib مستقل واحد يجمع النسختين، بدون Substrate / ElleKit:

1. **DomainSniffer**: يصيد ويعرض النطاقات والـ IP وDNS الخاصة بالتطبيق المضيف،
   مع حجب NextDNS، قواعد الاستبدال، وضع DNS/CHAT/ALL→8.8.8.8، صوت دخول الروم،
   وتسريع صوت المتكلمين.
2. **ServerTester**: اختبار ضغط WebSocket/HTTP لسيرفرك الخاص (العنوان الذي تضبطه بنفسك).
3. **AUTO TEST جديد** داخل شاشة `SERVER TEST`: فحص تلقائي للأهداف التي التقطها
   الـ sniffer، مع خيارين كما طلبت.

## الخياران الجديدان في SERVER TEST

- **ALL (الخيار الأول)**: يصيد **كل** النطاقات والـ IP/DNS التي التقطها الـ sniffer
  ويعمل عليها اختبار تلقائي. لكل هدف: حلّ DNS ثم اتصال TCP مباشر بالمنافذ
  التي رُصدت لها (أو `443` ثم `80`). تُحفظ النتيجة داخل كل سطر
  `🧪 OK/FAIL …ms` وداخل `data.json`.
- **CHAT (الخيار الثاني)**: يصيد فقط **IP وDNS الدردشة والكتابة أونلاين**:
  النطاقات التي تحتوي `chat` / `typing` / `online` / `presence` / `messag` /
  `websocket` / `mqtt` / `xmpp` / `agora` / `sendbird` / `pubnub` / `pusher` /
  `whatsapp` / `telegram` / `discord` وغيرها، إضافة إلى الـ IP التي تعلّمها
  الـ sniffer من حلّ هذه النطاقات، أو الـ IP المرتبطة بأحد هذه النطاقات.
  يختبرها تلقائياً بنفس طريقة `ALL`.

## التشغيل التلقائي

- اختر `ALL` أو `CHAT` في شاشة `SERVER TEST` → يشتغل الاختبار فوراً عند التفعيل،
  ثم كل `N` ثانية (30 / 60 / 120 / 300 / 600) **والتطبيق مفتوح بالمقدمة**.
- `AUTO: كل N ثانية` يغيّر الفاصل. `▶ اختبار الأهداف الآن` يشغّل يدوياً
  (ويعيد اختبار كل الأهداف). `📋 نسخ الأهداف` ينسخ جدولاً نصياً للحافظة.
- السجل `LOG` داخل الشاشة يعرض كل هدف ونتيجته، والقائمة الرئيسية تعرض
  نتيجة الفحص داخل كل سطر (`🧪 ...`).

> ملاحظة: الاختبار نشاط شبكي فعلي (DNS + TCP) — التطبيق المدمج يحتاج اتصالاً
> بالإنترنت. الفاصل التلقائي يعمل فقط أثناء فتح التطبيق في المقدمة لأنه قيد
> عام لنظام iOS، وليس نقصاً في الكود.

## خيارات الكيبورد (قسم «الكيبورد» في القائمة الرئيسية)

صفّ جديد فيه زرّان، يعملان على أي حقل كتابة داخل اللعبة/التطبيق (دردشة، بحث...):

- **`تكرار الأرقام: ON/OFF`** — تكتب `135` فتصير تلقائياً `135.135`.
  أثناء الكتابة: `1` ← `1.1` ثم `13` ← `13.13` ثم `135` ← `135.135`.
  زر المسح يتراجع رقماً رقماً (`135.135` ← `13.13` ← `1.1` ← فارغ).
- **`تفكيك الحروف: ON/OFF`** — تكتب `حسين` فتصير `ح س ي ن`.
  زر المسح يمسح الحرف مع مسافته. التشكيل يبقى ملتصقاً بحرفه.

### حساسية الكيبورد (بديل كل خيارات الإرسال التلقائي القديمة)

حُذفت خيارات «ارسال تلقائي / عدد الأرقام / ارسال عند التوقف / ارسال بعد الاكمال» لأنها كانت تتعارض مع بعض.
حلّ محلها صفّان:

- **`حساسية الكيبورد: ON/OFF`** — **لا يرسل أبداً وأنت تلمس الكيبورد أو تكتب. أول ما ترفع يدك يرسل الرسالة مرة واحدة.**
  كل حرف جديد يلغي الإرسال المنتظر، والمسح كذلك. لا يتكرر الإرسال إلا إذا كتبت شيئاً جديداً.
- **`الحساسية: ذكي AUTO / 0.05s / 0.1s / 0.2s / 0.4s`** — المهلة بين رفع يدك والإرسال.
  `AUTO` = **ذكاء على الجهاز بدون إنترنت**: يتعلّم إيقاع كتابتك (الأرقام وحدها والحروف وحدها)، والمهلة = (متوسط الفاصل + 1.5 × الانحراف) × معامل تعلّم ذاتي بين 0.05 و0.35 ثانية.
  إذا أرسل مبكراً (كتبت بعده مباشرة) يبطئ قليلاً، وكلما أصاب يتسارع. يفرغ التعلّم عند تغيير الوضع أو إعادة فتح التطبيق.
- **`أقل عدد أحرف: 1/2/3/4/6/8`** — لا يرسل إلا إذا الرسالة بهذا الطول أو أطول (يمنع إرسال حرف واحد بالغلط).
- **`اهتزاز عند الارسال: ON/OFF`** — اهتزاز خفيف يؤكد لك أن الرسالة أُرسلت.

مميزات إضافية:

- ينتظر اكتمال كتابة الـ IME (الحروف العربية المعلّقة) قبل الإرسال.
- يتجاوز حقول كلمة السر وشاشات الأداة نفسها.
- يعمل مع «تكرار الأرقام» و«تفكيك الحروف» معاً (الإرسال بعد تعديلهما للنص).
- إن ضغطت Return بنفسك يلغي الإرسال المنتظر.
- إخفاء الكيبورد يلغي أي إرسال منتظر.

حدّ تقني: كيبورد iOS النظامي يعمل في عملية منفصلة ولا يمرّر اللمس للتطبيق، فالتطبيق لا يرى إصبعك مباشرة؛
لذلك يعتمد على آخر حرف أُدخل + المهلة. أما الكيبورد الذي يمر لمسه عبر نافذة اللعبة (Unity مثلاً) فيُكتشف اللمس الفعلي ولا يرسل أبداً وإصبعك عليه.
الإرسال = محاكاة زر Return/Send في الحقل (قد لا يعمل مع زر إرسال مرسوم داخل اللعبة وليس من الكيبورد).

### إرسال بعدد الأرقام (منيو مصغّر)

- زر **`إرسال بعدد الأرقام: ON/OFF`** في قسم الكيبورد. عند تشغيله يظهر **منيو صغير مستقل** فوق التطبيق.
- المنيو الصغير مستقل عن القائمة الرئيسية: **يبقى ويعمل حتى لو أغلقت القائمة القديمة بـ ✕**، ويمكن سحبه لأي مكان.
- فيه: `−` و`+` لاختيار عدد الأرقام (1 إلى 20)، وأزرار سريعة 1–6، وعدّاد حيّ `3 / 5`.
- أول ما يكتمل العدد يرسل **فوراً بدون أي تأخير (0.00s)**: رقم واحد `1` يرسل مباشرة، وإذا اخترت 5 يرسل عند `12879`.
- يعدّ الأرقام المتتالية فقط (يدعم الأرقام العربية والإنجليزية)، والحرف أو الحذف يعيد العدّ.
- ✕ في المنيو الصغير يوقف الخيار ويخفيه.
- لا يتعارض مع «حساسية الكيبورد»: إذا أرسل بالأرقام يلغي إرسال الحساسية المنتظر.

### الكتابة السريعة (رسالة واحدة لآخر حقل دردشة فتحته)

- زر **`الكتابة السريعة: ON/OFF`** في قسم «الدردشة والصوت». عند تشغيله يظهر **منيو ثالث مستقل**
  فوق التطبيق (يبقى حتى لو أغلقت القائمة الرئيسية، ويمكن سحبه).
- اكتب رسالتك في حقل المنيو واضغط **`⬆︎ إرسال`** (أو Return): تُرسَل **فوراً ومرة واحدة فقط**
  إلى **آخر حقل كتابة ضغطت فيه فعلياً داخل التطبيق نفسه** — أي الدردشة/الروم الذي أنت فيه حالياً.
- لا يستهدف أكثر من حقل واحد ولا يكرر الإرسال تلقائياً؛ كل ضغطة على «إرسال» = رسالة واحدة لوجهة واحدة.
- **تأكيد إرسال حقيقي، فوري 0.00s**: بعد الضغط على إرسال يفحص لحظياً هل تفرّغ حقل الدردشة فعلاً (كما تفعل
  كل تطبيقات الدردشة بعد نجاح الإرسال). ✅ `أُرسلت فعلاً` يعني التطبيق استلمها، ⚠️ `لم تُرسل` يعني الحقل لم
  يتفرّغ بعد وتحتاج تتحقق يدوياً — بدون أي إعادة إرسال أو تكرار تلقائي. (الفحص الفوري قد يسبق تحديث بعض
  التطبيقات البطيئة لواجهتها، فيُظهر تحذيراً رغم نجاح الإرسال فعلياً — الإرسال نفسه غير متأثر).
- إن لم تكن قد فتحت حقل كتابة في التطبيق بعد (أو أغلقته)، يظهر تنبيه «افتح حقل الدردشة واضغط فيه أولاً»
  ولا يُرسل شيء.
- لا يعمل مع حقول كلمة السر ولا مع حقول شاشات الأداة نفسها.
- الإعداد يُحفظ في `settings.json` (`quickSendOn`).

### تحسين محرك WSOLA (أقوى محاذاة وجودة صوت)

قوّيت محرك محاذاة المقاطع المستخدم بالسرعة الحية:
- **ارتباط طبيعي كامل بمتوسط صفري (Zero-mean Normalized Cross-Correlation)** بدل الارتباط الخام القديم — ما عاد ينحاز لمقاطع منخفضة الطاقة فقط لأنها "تشبه" رقمياً، فالمحاذاة بين المقاطع أدق وأثبت.
- **بحث خشن ثم دقيق (coarse-to-fine)**: يفحص أولاً نطاق المحاذاة كامل بخطوات متباعدة، ثم يدقّق حول أفضل نتيجة بخطوة 1. نفس دقة الفحص الكامل تقريباً لكن بكلفة معالجة أقل.
- **نافذة Hann (جيب تجميعي)** بدل النافذة المثلثية القديمة — تلاشٍ أنعم بين المقاطع المتراكبة، يقلّل الطنين/الخشونة الدورية (artifact) المعروفة بخوارزميات WSOLA البسيطة.
- **تخطّي البحث بمقاطع الصمت**: لو ما فيه إشارة فعلية (طاقة شبه صفرية)، يمر مباشرة بلا بحث محاذاة — أسرع وأثبت بدل محاذاة عشوائية بصمت لا معنى له.

النتيجة: صوت أنظف وأقل تقطيعاً عند السرعات العالية (x3/x4) بالذات، بنفس استهلاك المعالج تقريباً.

## محاولة إضافة Agora/Zego أحدث (غير ممكنة فنياً هنا)

تم السؤال عن تضمين نسخ أحدث من Agora/Zego داخل المشروع. هذا **غير ممكن من هذا النوع من المشاريع (dylib حقن خارجي)**:
أي نسخة جديدة تُضاف هنا ستكون منفصلة تماماً وغير متصلة بمنطق اللعبة أو سيرفراتها، فلن تنقل أو تستقبل أي صوت حقيقي — فقط حجم أكبر للملف بلا أي فائدة عملية.
تحديث SDK الفعلي يتطلب إعادة بناء تطبيق يلا لودو نفسه من مطوّريه، وهذا خارج نطاق أي تعديل من جهة العميل (client-side).

## محرك الصوت (جديد)

فحصت ملف الـIPA الفعلي للعبة ووجدت أنها تضمّن **محركين معاً**:
- **Agora RTC SDK 3.7.3** (AgoraCore, AgoraRtcKit, AgoraSoundTouch, AgoraAIDenoiseExtension, Agorafdkaac...) — هو المحرك اللي تبنى عليه هوك "الصوت لكل متكلم" (JOIN SOUND، السرعة الحية الدقيقة، تسريع الصوت).
- **Zego LiveRoom 6.34.63 / Zego Engine 1.3.6.6** — موجود بالتطبيق أيضاً كمحرك بديل.

أضفت قسم **«محرك الصوت»** الجديد بالمنيو:
- يفحص عند كل فتح أي الفريموركات فعلاً مضمّنة بنسخة اللعبة المثبتة عندك (مو بحث إنترنت، بل قراءة مباشرة من ملفات اللعبة نفسها)، ويعرض أرقام إصداراتها.
- يعرض عبر أي محرك تعمل السرعة الحية الآن: "عبر Agora" (الهوك الدقيق لكل متكلم) أو "عبر الوضع العام" (يعمل تلقائياً مع Zego أو أي محرك ثاني).
- زر **🔄 إعادة فحص محرك الصوت** يعيد الفحص يدوياً (مفيد لو فتحت الروم بعد فتح المنيو).
- **تبديل تلقائي ذكي (مرة واحدة فقط):** إذا ما كانت قناة Agora (`AgoraRtcChannel`) متوفرة بنسخة اللعبة، يُفعَّل تلقائياً خيار **«كل الصوت (Zego وغيره)»** بدل ما تكتشفه بنفسك، حتى تستمر السرعة الحية تعمل مهما كان المحرك الفعلي. بعدها يحترم اختيارك ولا يكرر التبديل.

## السرعة الحية (منيو صغير ثانٍ)

**تحديث:** الافتراضي الآن **تجميع = 0.0 وتأخير = 0.0** (بلا تجميع، تشغيل شبه مباشر فور التفعيل).
زر **⏱ تأخير** يدوّر الآن بين: `0s → 5s → 30s → 1m → 5m → 15m → 30m`، فأقصى مدة تجميع/لحاق صارت **30 دقيقة**.

⚠️ **تنبيه مهم بخصوص 30 دقيقة:** كل دقيقة تجميع تحتاج تقريباً 5.5 إلى 6 ميغابايت ذاكرة لكل متكلم يُعالَج (حسب معدل العينة)،
فـ30 دقيقة تعني نحو **170 ميغابايت لكل محرك صوت نشط**. إذا كان خيار **«كل الصوت (Zego وغيره)»** مفعّلاً فهناك محرك واحد فقط
(آمن). أما إذا كان متوقفاً ويعالج عدة متكلمين من Agora في نفس الوقت، فقد تتضاعف الذاكرة بسرعة وتُسبب إغلاق اللعبة من iOS
(Jailbreak/Memory Pressure) عند استخدام تأخير كبير (دقائق) مع عدة متكلمين معاً. **إذا بغيت تستخدم تأخيراً بالدقائق، فعّل
«كل الصوت: ON» لتبقى الذاكرة ضمن حد آمن.** تأخير بالثواني (0 إلى 60s) آمن دائماً مهما كان عدد المتكلمين.


- زر **`السرعة الحية: ON/OFF`** في قسم «الدردشة والصوت». عند تشغيله يظهر **منيو صغير مستقل** (يبقى حتى لو أغلقت القائمة الرئيسية، ويمكن سحبه). ✕ فيه يوقف الخيار ويخفيه.
- فيه: أزرار السرعة `x1 / x1.5 / x2 / x3 / x4`، و`⏱ تأخير` (5 / 10 / 20 / 30 ثانية)، وزر `● LIVE`، وسطر حالة حيّ (`🟢 مباشر` / `⏳ تجميع` / `🚀 لحاق`).
- **يلتقط الصوت تلقائياً من:**
  - **Agora** (صوت المتكلمين قبل الخلط، لكل متكلم على حدة) عبر محرك WSOLA يحافظ على النغمة.
  - **AVPlayer / AVAudioPlayer** (أي مشغّل صوت/فيديو أونلاين في التطبيق): تُطبَّق السرعة عليها فور تشغيلها، ويُعاد ضبطها عند تغيير الزر. ملاحظة: `AVAudioPlayer` يدعم حتى 2x فقط. صوت دخول الروم الخاص بالأداة لا يتأثر.
- **البث الحي ليس ملفاً جاهزاً:** لا يمكن سماع الكلام أسرع من وصوله. لذلك عند اختيار x2 أو أكثر: يجمع التأخير المختار **بصمت**، ثم يشغّل المتجمّع **مسرّعاً بنغمة طبيعية** حتى يلحق البث الحي، وبعدها يرجع تلقائياً 1x بلا تقطيع. اضغط **نفس زر السرعة** مرة ثانية لبدء تجميع ولحاق جديد، و`LIVE` للقفز للبث الحي فوراً.
- مثال: تأخير 20s على x2 = 20 ثانية صمت ثم نحو 20 ثانية تسريع. على x4 يلحق خلال نحو 7 ثوانٍ.
- المحرك اختُبر بمعزل عن اللعبة بإشارة تجريبية: صمت التجميع كامل، النغمة بقيت 220Hz أثناء اللحاق، والتسريع x2 فعلي.
- الإعدادات تُحفظ في `settings.json` (`liveSpeedOn` / `liveSpeed` / `liveDelay`).
- **`🌐 كل الصوت (Zego وغيره)`** (زر داخل المنيو الصغير): بما أن بعض الغرف تعمل بـ **Zego** (موجود بالـ IPA: ZegoLiveRoom / ZegoLiveRoomEngine) وليس Agora، هذا الوضع يلتفّ حول دوال تشغيل الصوت (AudioUnit render callbacks) فيعالج **المخرج النهائي** مهما كان المحرك، بنفس منطق التجميع ثم اللحاق. تنبيه: يشمل كل ما يمر بتلك الوحدة (أصوات اللعبة أيضاً) لأنه على المخرج النهائي، وعند تشغيله يتوقف مسار Agora الخاص حتى لا يُعالَج الصوت مرتين. لا يعمل إن كان المحرك يمرّر الصوت عبر AUGraph داخلياً بدل `AudioUnitSetProperty`.
- حدود: الستيريو يُدمج إلى أحادي أثناء المعالجة. إذا كان «VOICE SPEED» القديم مفعّلاً معه، تأخذ «السرعة الحية» الأولوية. أصوات الألعاب المدمجة (FMOD/Unity) التي لا تمر عبر Agora أو AVFoundation لا تُلتقط.

### الدردشة المباشرة (عميل WebSocket لسيرفرك الخاص)

- زر **`الدردشة المباشرة: ON/OFF`** في قسم «الدردشة والصوت». عند تشغيله يظهر **منيو ثانٍ مستقل**
  فوق التطبيق (نافذة منفصلة، تبقى حتى لو أغلقت القائمة الرئيسية، ويمكن سحبها).
- داخل المنيو: حقل لعنوان سيرفرك (`IP:PORT`، مثال `1.2.3.4:8080`) وزر **حفظ** يعيد الاتصال بالعنوان
  الجديد، وسجل يعرض كل رسالة تصل مع وقتها، وحالة الاتصال (متصل / يحاول الاتصال… / غير متصل).
- يتصل عبر WebSocket (`ws://`) ويعيد المحاولة تلقائياً كل 3 ثوانٍ إذا انقطع الاتصال وما زال الخيار مفعّلاً.
- يقرأ الرسائل بصيغة `{"type":"message","text":"..."}` (وأيضاً نصاً عادياً لو وصل).
- **✕** داخل المنيو يوقف الخيار ويقطع الاتصال ويخفي المنيو.
- إعداداته (تشغيل/عنوان) تُحفظ في `livechat.json` داخل مجلد بيانات الأداة.

**سيرفر تجريبي:** ملف `server/chat-server.js` في المستودع سيرفر Node.js بسيط (مكتبة `ws`) يبث أي رسالة
تصله لكل المتصلين. شغّله على جهازك أو VPS خاص بك:

```
cd server
npm init -y && npm install ws
node chat-server.js
```

ثم ضع عنوان جهازك (IP الحقيقي، ليس 127.0.0.1، إلا إذا كان الجهاز نفسه) في حقل المنيو داخل التطبيق.
هذا السيرفر **لا** يُبنى داخل الـ dylib — يعمل بشكل منفصل على حاسوبك، والتطبيق يتصل به فقط كعميل.

ملاحظات:

- الخيارات تُحفظ في `settings.json` (`kbRepeatNums` / `kbSplitLetters` / `kbSense` / `kbSenseMode` / `kbMinChars` / `kbHaptic` / `digitSend` / `digitCount`) ويعملان لحظياً بلا إعادة تشغيل.
- لا يعملان داخل شاشات الأداة نفسها (حقل البحث، رابط البروكسي...) ولا في حقول كلمة السر.
- يمكن تفعيل الاثنين معاً (الأول للأرقام والثاني للحروف).
- إن استخدمت اقتراحات الكيبورد (شريط الكلمات المقترحة) فقد تُدرَج الكلمة كاملة بدون تفكيك عبر آلية أخرى في iOS؛ عطّل الاقتراحات لنتيجة أدق.

## PROXY — اتصال عبر أي رابط بروكسي

في القائمة الرئيسية (قسم **الشبكة وDNS**) صفّ جديد فيه ثلاثة أزرار:

- **`PROXY: ON/OFF`** — تشغيل/إيقاف (يعرض عدد الاتصالات التي مرّت عبر البروكسي).
- **`PROXY LINK`** — الصق/اكتب الرابط ثم **حفظ وتفعيل** (أو **لصق من الحافظة وتفعيل**). يُختبر تلقائياً بعد الحفظ.
- **`TEST`** — يفتح نفقاً عبر البروكسي ويعرض **IP الخروج** وزمن الاتصال.

الصيغ المدعومة:

| الصيغة | مثال |
|---|---|
| SOCKS5 | `socks5://user:pass@host:1080` (أو `socks5h://` أو `socks://`) |
| HTTP (CONNECT) | `http://user:pass@host:8080` |
| رابط تيليجرام | `https://t.me/socks?server=H&port=P&user=U&pass=W` أو `tg://socks?...` |
| بدون scheme | `host:port` أو `host:port:user:pass` (المنافذ 80/8080/3128/8888... تُعامل HTTP والباقي SOCKS5) |

كيف يعمل:

- **TCP الخام** (مكتبات التطبيق التي تستدعي `connect`): تُنشأ المصافحة مع البروكسي ثم الاتصال بالوجهة. الوجهات المحلية/الخاصة (127.x, 10.x, 192.168.x...) لا تُمرَّر.
- **NSURLSession** (HTTP/HTTPS/WebSocket): يُحقن البروكسي في إعدادات الجلسات عند إنشائها (iOS 17+ مع مصادقة أصلية).
- الرابط يُحفظ في `Documents/AflatoonSuite/proxy.json` ويُفعَّل تلقائياً عند فتح اللعبة قبل أي اتصال.
- عند فشل البروكسي تفشل الاتصالات (لا تسريب مباشر) — أوقف البروكسي من الزر إن تعطّل.

حدود يجب معرفتها:

- **UDP غير مدعوم** (مثل الصوت الذي يمر عبر UDP). DNS يُحلّ محلياً قبل الاتصال.
- **vmess / vless / trojan / ss / hysteria** غير مدعومة (تحتاج نواة Xray أو sing-box).
- الجلسات التي أنشأها التطبيق **قبل** التفعيل لا تتأثر حتى إعادة فتح اللعبة، و`NSURLSession.sharedSession` لا يمكن حقنها.

## ServerTester (اختبار الضغط لسيرفرك الخاص)

في نفس شاشة `SERVER TEST`:

- **WS**: عنوان WebSocket لسيرفرك (اضغط لتعديله).
- **HTTP**: عنوان فحص صحة اختياري (اضغط لتعديله).
- **CLIENTS / DURATION / RATE**: تدوير بين قيم جاهزة (5-100 عميل، 10-120 ثانية، 1-20 رسالة/ثانية).
- **RUN NOW**: يشغّل اختبار الضغط فوراً ويطبع النتيجة بسجل الشاشة
  (`NSURLSessionWebSocketTask` + HTTP health checks)، مثل `server-tester.js` الأصلي.
- **AUTO LOAD**: يشغّل اختبار الضغط تلقائياً كل `N` دقيقة (15/30/60/120) **والتطبيق مفتوح بالمقدمة**.

استخدمه **فقط على سيرفرك الخاص**. العنوان الافتراضي وهمي
(`your-server.example.com`) ولازم تغيّره بنفسك.

## الدول 🚩 (جديد): علم في الشات → يكتب الاسم أو العاصمة

- صف جديد في القائمة (قسم «الدردشة والصوت»): **`الدول (علم ← اسم/عاصمة): ON/OFF`** يُظهر/يُخفي زراً عائماً صغيراً **🚩** مستقلاً عن القائمة (يظهر تلقائياً عند فتح اللعبة).
- اضغط 🚩 فتظهر لوحة صغيرة: **`🌍 اسم الدولة`** أو **`🏛 العاصمة`** (اضغط الخيار الفعّال مرة ثانية ليتوقف) و **`⏹ إيقاف`**. الاختيار محفوظ.
- إذا نزل أي شخص علماً في الشات (أو **علمين أو أكثر في نفس الرسالة**) يكتب **كل** الأسماء/العواصم بالترتيب مفصولة بمسافة، فوراً في حقل الكتابة المفتوح (بدل محتواه). مثال: 🇮🇶🇫🇷 ← `العراق فرنسا` أو `بغداد باريس`.
- **`⬆︎ إرسال: ON/OFF`** يرسل بعد الكتابة (افتراضي OFF = يكتب فقط).
- **`الرسالة: أعلام فقط / أي نص فيه علم`**: الأول لا يتحرك إلا إذا الرسالة أعلام فقط (يتجنب أعلام الملفات الشخصية)؛ الثاني يلتقط العلم حتى لو معه نص.
- يعمل فقط إذا نص الدردشة UILabel/UITextView عادي، ويحتاج حقل كتابة مفتوحاً (أو آخر حقل كتبت فيه). 196 دولة بالعربي.
